# 完成标准

## 目标

把 an-task 的"分流判定"与"是否建 Artifact"分离表述，并建立可判定的客观规模标准与迭代膨胀再评估机制，使小改动可跳过建仓、但任何执行态请求都不能跳过 an-task 分流。

## 完成标准

- [ ] AC-1: an-task 明确"分流判定 ≠ 建 Artifact"：任何进入执行态的请求都必须先判定 L0-L3；L0/L1 只是不创建 Artifact，不是不判定。
- [ ] AC-2: flow-policy 为 L0/L1 补充客观规模判据：仅修改 1 个前端文件且不涉及后端、不新增文件/接口/依赖时才允许 L0/L1。
- [ ] AC-3: flow-policy 明确规模触发线：预计变更涉及 3 个以上文件或跨前后端/后端接口/数据层时，至少使用 L2，必须创建 Artifact。
- [ ] AC-4: flow-policy 与 an-task 加入迭代膨胀再评估：执行中连续迭代达 3 轮或实际改动超出初始规模判断时，暂停并向用户确认是否升级流程并创建 Artifact。
- [ ] AC-5: 契约测试覆盖上述规模判定与再评估规则，全部测试通过。
