# 任务背景

an-task 再次出现不主动触发的问题。AI 反馈的三条原因：

1. an-task 自身允许跳过：L0/L1"小改动可不创建 artifacts"被误读为"可直接实现、跳过 an-task 分流"。
2. 任务边界在对话中膨胀：从"加按钮"逐步膨胀为加后端 API、改状态映射、修复搜索过滤、拆组件、加 DevOps 预留、加撤回，缺乏"任务已开始"的决策点。
3. 没有规模感知的触发条件：缺少"什么算小改动"的客观标准；"加 3 个按钮"和"加后端服务+路由+改映射+修 auth"都是"小改动"。

用户建议优化方向：
1. 按文件变更数量自动判定：预计变更涉及 3 个以上文件或跨前后端时，自动走完整流程，不能跳过。
2. 对话中检测膨胀：已完成的修改超出初始判断规模时（如第 3 轮迭代后），主动询问是否创建 artifacts。
3. 明确"小改动"的客观标准：如"仅修改 1 个前端文件且不涉及后端"才允许跳过。
