# AI Native 可执行动作清单

将文档型规范转成 AI 可执行的动作清单：明确动作、工作目录、用途、置信度和来源。

## 何时使用

- 初始化后需要生成 `.agents/recipes.json`。
- 用户问“怎么验证”“怎么构建”“有哪些测试入口”“怎么检查”。
- 任务实现后需要选择最小验证动作。
- 工具链或脚本变化后需要刷新可执行动作清单。

## 快速探测

```bash
node .agents/skills/an-recipes/scripts/detect-recipes.mjs --root projects --format markdown
```

写入结构化动作清单：

```bash
node .agents/skills/an-recipes/scripts/detect-recipes.mjs --root projects --write .agents/recipes.json
```

## 动作选择原则

| 任务类型 | 优先动作 |
|----------|----------|
| 纯文案/样式 | 格式检查或相关单测 |
| 类型、接口、模型变更 | 类型检查和测试 |
| 构建链路变更 | 构建和测试 |
| 代码生成、数据模型变更 | 代码生成、类型检查和测试 |
| 文档/内容变更 | 链接检查、字数统计、格式检查、样例渲染 |
| 数据/设计变更 | 数据校验、资源导出、预览生成 |
| 多工作区改动 | 每个受影响工作区运行最小动作 |

## 执行约束

- 先读 `.agents/recipes.json`；不存在或过期时运行探测脚本。
- 不自动运行常驻服务，除非验证需要且用户允许。
- 高成本动作先说明原因；网络安装、数据变更、破坏性命令需要用户确认。
- 动作失败时，记录失败动作、工作目录、退出码和关键输出。

## 非代码工作区

当 `projects/` 下没有可识别的代码工程时，探测脚本会返回空或最小结构。此时 AI 应根据任务类型自行推断最小验证动作（如“读取并核对生成的 Markdown”），并在验证报告中说明。
